fluent-measures on GitHub

Parse everyday height and weight text into structured data

A JavaScript and TypeScript library for health apps, fitness trackers and web forms. It reads metric and imperial units, and numbers in digits or in words, as in 5' 11" or five feet eleven inches.A JavaScript and TypeScript library for input like 5' 11" or five feet eleven inches.

$npm install @afahy/fluent-measures
Get started View on npm
View Markdown Agent index (llms.txt) Docs for your version

  • Metric and imperial: ft, in, cm, m, lb and kg; convert with normalizedUnit.

  • Flexible input: Digits or words, thousands separators and decimal commas; allow unit typos with fuzziness.

Install

Add the package with your package manager.

npm

npm install @afahy/fluent-measures

yarn

yarn add @afahy/fluent-measures

pnpm

pnpm add @afahy/fluent-measures

Small footprint. No runtime dependencies. At most 6.0 kB for ESM and 6.0 kB for CommonJS, minified and compressed with Brotli.

Quick start

Import parseMeasurement with ES modules or CommonJS, pass it the text to read, and check the result before you use it. The unit in the text identifies a height or weight, so these inputs need no options.

ES modules

import { parseMeasurement } from '@afahy/fluent-measures';

const result = parseMeasurement('6 ft');
/* ✓ Returns:
{
  value: 6,
  unit: 'ft',
  type: 'height',
  matches: [
    { value: 6, unit: 'ft' }
  ],
  raw: '6 ft'
}
*/
if (result) {
  console.log(result);
}
import {
  parseMeasurement,
} from '@afahy/fluent-measures';

const result =
  parseMeasurement('6 ft');
if (result) {
  console.log(result);
}

Read only one type

Set type when a field expects one kind of measurement, such as a weight. The parser then reads only that kind, so a height typed into a weight field returns null. Use type: 'height' for a height field.

TypeScript 
const accepted = parseMeasurement(
  'eighty kilograms',
  { type: 'weight' },
);
/* ✓ Returns:
{
  value: 80,
  unit: 'kg',
  type: 'weight',
  matches: [
    { value: 80, unit: 'kg' }
  ],
  raw: 'eighty kilograms'
}
*/

const rejected = parseMeasurement('6 ft', { type: 'weight' });
/* ✓ Returns: null */
const accepted = parseMeasurement(
  'eighty kilograms',
  { type: 'weight' },
);

const rejected = parseMeasurement(
  '6 ft',
  { type: 'weight' },
);
Returns

accepted80 kga weight

rejectednulla height in a weight field

Convert to one unit

Set normalizedUnit to get the result in the unit that you store. The compound height below combines 5 ft and 11 in: (5 × 12 + 11) × 2.54 = 180.34 cm. matches keeps the original parts in their own units.

Height conversion 

parseMeasurement('5\' 11"', { type: 'height', normalizedUnit: 'cm' });
/* ✓ Returns:
{
  value: 180.34,
  unit: 'cm',
  type: 'height',
  matches: [
    { value: 5, unit: 'ft' },
    { value: 11, unit: 'in' }
  ],
  raw: '5\' 11"'
}
*/
parseMeasurement('5\' 11"', {
  type: 'height',
  normalizedUnit: 'cm',
});
Returns

180.34 cmmatches: 5 ft and 11 in

Weight conversion 

parseMeasurement('150 lbs', { type: 'weight', normalizedUnit: 'kg' });
/* ✓ Returns:
{
  value: 68.0388555,
  unit: 'kg',
  type: 'weight',
  matches: [
    { value: 150, unit: 'lb' }
  ],
  raw: '150 lbs'
}
*/
parseMeasurement('150 lbs', {
  type: 'weight',
  normalizedUnit: 'kg',
});
Returns

68.0388555 kgmatches: 150 lb

Without conversion, feet and inches combine into inches. Written-out numbers work too:

five foot ten{ type: 'height' }
70 in

matches keeps 5 ft and 10 in, just as it keeps the parts above.

Numbers without a unit

People sometimes type only a number, for example in a calculator field labeled “Height (in)”. Set defaultUnit to that source unit. Written units take precedence. normalizedUnit chooses the output unit and measurement type; it never supplies a source unit. There is no magnitude guessing: 1.8 with a centimeter default means 1.8 cm.

TypeScript 
parseMeasurement('72', {
  defaultUnit: 'in',
});
/* ✓ Returns:
{
  value: 72,
  unit: 'in',
  type: 'height',
  matches: [
    { value: 72, unit: 'in' }
  ],
  raw: '72'
}
*/
Returns

72 insource default: inches

Spelling errors in units

Set fuzziness to read unit names that have spelling errors. Without it, a unit name must be exact, so the same text returns null. Each letter that is added, removed or changed is one error, and fuzziness is the largest number of errors in a word. Limits says what fuzzy matching can get wrong.

TypeScript 
// With fuzzy matching
const result = parseMeasurement('5 foots 10 inc', { fuzziness: 2 });
/* ✓ Returns:
{
  value: 70,
  unit: 'in',
  type: 'height',
  matches: [
    { value: 5, unit: 'ft' },
    { value: 10, unit: 'in' }
  ],
  raw: '5 foots 10 inc'
}
*/

// Without it
const strict = parseMeasurement('5 foots 10 inc');
/* ✓ Returns: null */
// With fuzzy matching
const result = parseMeasurement(
  '5 foots 10 inc',
  { fuzziness: 2 },
);

// Without it
const strict = parseMeasurement(
  '5 foots 10 inc',
);
Returns

result70 inunit names read with errors

strictnullunit names must be exact

API

The package exports one function, parseMeasurement, and the ParseOptions, ParsedValue, Unit and MeasurementType types.

parseMeasurement

Reads one height or weight from a string. When it returns null, Troubleshooting lists the causes to look for, including input longer than maxLength. For string input it validates options before length or text: the options object, maxLength, type, normalizedUnit, defaultUnit, retired options, then dimension conflicts. Invalid options throw even for empty or overlong strings. Non-string runtime input returns null before reading options. Empty strings and null values for type or normalizedUnit count as absent.

To migrate, remove allowUnqualified and inferUnit; either throws when defined, including false. An explicitly undefined property is absent. Use defaultUnit: 'in' or 'lb' for imperial fields, 'kg' for metric weight, and choose 'm' or 'cm' explicitly for metric height.

Limits

Some text returns null, or a result that you might not expect.

Input Result
12st 4lb
nullStone, ounces and grams aren't supported
150-180 lbs
nullA range isn't one measurement
70 kg (154 lbs)
nullTwo weights, even when they agree
210 lbs to 180 lbs
nullA range is not one measurement

The whole entry must be one complete measurement, including supported compounds such as 5 ft 11 in. Two heights or two weights return null, even when they agree. For exactly one complete height and one complete weight, set type or normalizedUnit to select one. Both expressions must be valid; without a selector the result is null.

Only supported wrappers may surround a measurement

I'm five foot eleven tall and about 180 cm are supported. Unrelated prose is not: Top 10 in the class returns null. Quotation marks and brackets around the entry or a number are not supported either: (180 cm) returns null. Fuzzy matching does not discard leftover text.

PARSING.md gives all the rules, with examples.

Troubleshooting

If parseMeasurement returns null, look for these causes:

  1. The unit isn't supported. See Supported units.
  2. The text doesn't say whether it is a height or a weight. Set type.
  3. A number has no unit. Set defaultUnit to the source unit shown by the field.
  4. A unit name has a spelling error. Set fuzziness to 1 or 2.
  5. The text has a range, duplicate measurements, an incomplete fragment or unsupported text. See Limits.
  6. The input isn't a string. Non-string input returns null at runtime; the TypeScript parameter remains string.
  7. The raw input.length, before trimming, exceeds maxLength (default 1,000). Set a larger maxLength or Infinity for no limit. Length counts UTF-16 code units, as JavaScript does.

If none of these explains the result, search the GitHub issues. To report a bug, open an issue with the input, the options and the result that you expected.
